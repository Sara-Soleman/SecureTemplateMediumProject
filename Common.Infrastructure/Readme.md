توثيق طبقة البنية التحتية المشتركة (Common.Infrastructure Layer)تختص هذه الطبقة (Common.Infrastructure) بتنفيذ التفاصيل التقنية الخارجية والربط مع الأنظمة الموزعة، وتحديداً إدارة وتوجيه أحداث التكامل عبر وسيط الرسائل Apache Kafka.🗂️ هيكلية المجلدات والمكونات الرئيسية1. مجلد الـ Messaging (المراسلة وتكامل الأنظمة)KafkaIntegrationEventConsumer.class: يجمع هذا الكلاس بين صفتين أساسيتين (IIntegrationEventConsumer و IIntegrationEventDispatcher) لإدارة الاستهلاك والتوزيع الآلي للرسائل القادمة من Kafka:الاستهلاك المستمر (ConsumeAsync): يدخل في حلقة عمل مستمرة (while) لمراقبة وسيط Kafka عبر _consumer.Consume()، وعند وصول رسالة يقوم بمطابقة Topic الرسالة مع القاموس المعرف _eventTypeMappings لتحويل نص الـ JSON الوارد إلى كلاس C# حقيقي.   التوجيه الديناميكي (DispatchAsync): يبحث عن المعالج (Handler) المناسب للحدث المستلم داخل قاموس المعالجات _handlers، ومن ثم يستدعي ميثود المعالجة (HandleAsync) بشكل ديناميكي وآمن باستخدام تقنية الـ Reflection لتنفيذ المهام المطلوبة (مثل تحديث قواعد البيانات الخارجية أو إرسال الإشعارات).   التعامل الآمن وإغلاق الاتصال: يدعم التعامل الهادئ عند الإيقاف (Graceful shutdown) عبر اصطياد استثناءات الإلغاء، ويضمن إغلاق اتصال الـ Consumer في نهاية دورة الحياة (finally).



ما هي طبقة Common.Infrastructure؟هي الطبقة المسؤولة عن الربط مع العالم الخارجي والتقنيات التقنية التحتية (مثل قواعد البيانات، ووسطاء الرسائل، والخدمات السحابية). بينما الطبقات الداخلية تفكر "كيف نعمل؟"، هذه الطبقة تفعل "كيف ننفذ تقنياً؟".🔍 ماذا تفعل وماذا ترسل/تستقبل؟تتواصل مع وسطاء الرسائل الخارجية (مثل Kafka):ماذا تفعل؟ تحتوي على أدوات مثل مستهلك الأحداث (KafkaIntegrationEventConsumer) الذي يراقب باستمرار رسالة Kafka عبر حلقة عمل (while).   ماذا تستقبل وترسل؟ تستقبل رسائل الـ JSON القادمة من الخارج، وتقوم بفك تشفيرها (Deserialization) ومطابقتها مع الأنواع البرمجية (_eventTypeMappings)، ثم تمررها ديناميكياً لتشغيل المعالجات الخاصة بها باستخدام تقنية الـ Reflection.   تتولى إدارة الاتصالات الخارجية وإغلاقها بأمان:تضمن التعامل السليم مع الإيقاف الهادئ (Graceful shutdown) وإغلاق قنوات الاتصال بالـ Consumer في النهاية (finally) لضمان عدم حدوث تسريب في الموارد.   🌱 هل هي ثابتة أم قابلة للتعديل مستقبلاً مع المشاريع الجديدة؟نعم، بل هي أكثر طبقة تتوسع وتتغير مستقبلاً!كلما أردت في مشروع جديد ربط نظامك بتقنية جديدة (مثل إضافة دعم لـ RabbitMQ بجانب Kafka، أو ربط خدمة تخزين سحابي جديدة، أو التعامل مع قاعدة بيانات مختلفة)، فإن التعديلات والإضافات تتم هنا في طبقة الـ Infrastructure دون أن تمس نظافة طبقات التطبيق أو النواة الداخلية.
